# pwhelper · 浏览器表单自动填充助手

零依赖的 Chrome 扩展（Manifest V3）。把登录页里的输入框「点一下」记下来，配上要填的内容，之后一键或自动回填；配置可导出成 JSON，换浏览器时导入即可复用。

- 记录：鼠标点选输入框 → 填写标签与内容 → 持久化保存，一个页面可记录任意多个字段
- 填充：按站点自动列出已保存的方案，一键填充；可开启「点开插件即自动填充」
- 轻量：**不在任何网站常驻运行脚本**，只有你点开插件那一刻才注入，用完即待命在下一次会话
- 迁移：全部配置导出为结构化的 JSON 文件，支持文件 / 粘贴两种导入方式
- 兼容：使用原生 setter 赋值并派发 `input` / `change` / `keyup`，React、Vue 等受控表单同样生效

## 一、安装

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 右上角开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本目录（`d:/code/pwhelper`）
4. 建议把扩展固定到工具栏，方便点击

无需 npm 安装、无需构建。修改代码后在扩展管理页点「刷新」即可生效（内容脚本改动需同时刷新目标页面）。

## 二、使用说明

### 记录一个站点

1. 打开需要登录的网页
2. 点击工具栏图标 → 切换到「记录」页签 → 点「开始拾取输入框」（弹窗会自动关闭）
3. 回到页面：鼠标一动就会出现顶部提示条，鼠标划过输入框会出现**霓虹描边高亮**，点击要记录的那个输入框
4. 页面右下角弹出浮层，填写：
   - **方案名称**：同一站点可以有多套（如「工作号」「个人号」）
   - **字段标签**：如「用户名」「密码」「验证码」
   - **填充内容**：真正要填进去的值
   - **敏感内容**：勾选后在列表里掩码显示
5. 点「保存，继续拾取」可连续记录多个字段；全部记完后点「完成」
6. 按 `Esc` 可随时退出拾取模式

> 站点按「主机名 + 端口」区分：`a.com:8080` 与 `a.com:9090` 是两套独立配置，互不影响。

记录过程中弹窗被关闭也没关系，捕获结果会暂存在会话里，重新打开插件即可继续补充或保存；若中途刷新了页面，用「继续在页面拾取」可重新进入拾取模式并保留已捕获的字段。

**iframe 里的登录框也能记录**：内容脚本会注入到页面的所有 frame（含嵌套 iframe），鼠标移到哪个 frame，那个 frame 就接管拾取 UI，同一时刻只会出现一套界面；填充时后台会把请求广播给所有 frame，各自填自己能定位到的字段，因此在 iframe 里录的字段也能正确填回去。

### 浏览器原生登录弹窗（HTTP Basic 认证）

像 Knox 网关（`WWW-Authenticate: BASIC`）、YARN/CDH 集群后台、路由器管理页这类站点，登录框是**浏览器自己画的**，不属于网页内容 —— 这种情况下页面是空白的 `401`，DOM 里连一个输入框都没有，任何扩展都无法用「拾取」去记录它。

这类站点交给**网络层**处理：

1. 首次访问照常弹出浏览器的原生登录框 → 打开插件，「填充」页签会识别出这种情况并提示
2. 在右下角卡片里一次性录入账号密码 → 自动保存并重新加载页面
3. 之后访问该站点时，扩展在网络层直接用保存的凭据应答，**不再弹任何登录框**

- 站点旁边也会锚定端口，所以 `10.0.0.2:30002` 可以与同主机的其他端口用不同凭据
- 凭据错误连续被拒时会自动停止接管，把控制权交回浏览器原生弹窗，不会反复重试
- 也可在「管理」页签为每个站点直接编辑或清除这套凭据（默认掩码，点 👁 查看）
- 它会随配置文件一起导出/导入（选择加密导出时一并被加密）；两边都有时，导入会把它作为**冲突项**让你裁决保留哪一套

### 填充

- 打开同一站点 → 点击插件 → 「填充」页签会列出本站点所有方案 → 点「填充」
- 打开方案上的「点开即填充」开关后，之后每次点开插件都会自动填入（最多重试 10 次 × 400ms，适配 SPA 异步渲染）
- 填充失败会提示具体是哪个字段没找到，可到「管理」页删除旧字段后重新记录

> **触发时机**：插件不会在每个网页里常驻监听，打开页面时也不会自动做事。只有你点开插件时，才会把内容脚本注入当前标签页，随后才可能发生拾取或填充。因此原来「打开页面自动填充」已改为「点开插件时自动填充」——牺牲一点无感体验，换掉全站常驻脚本。

### 管理

「管理」页签按站点分组展示全部配置，可以：

- 顶部搜索框**模糊过滤**：匹配配置名称、站点标识、匹配方式、方案名与字段标签，多个关键词用空格分隔（同时满足）；默认展示全部，清空即恢复
- 每个站点的**配置名称**（默认与站点标识相同）与**匹配模式**各占一行：名称可直接改；匹配方式可选主机名 + 端口 / 主域名含子域名 / URL 前缀，后面的输入框是该站点的标识（如 `10.0.0.2:30002`），也可直接改成别的主机名或端口
- HTTP 认证（账号 / 密码）**只在已经存过凭据的站点上出现**，不占没用到该功能的站点版面
- 直接修改每个字段要填充的内容（敏感项默认掩码，点 👁 切换显示）
- 开关自动填充、删除字段 / 方案 / 站点

### 导出

管理页签右上角「导出」会先弹出选项：

- **是否加密**：默认不加密；打开开关后需要输入密码并确认（至少 6 位）
  - 明文导出文件名 `pwhelper-config-YYYYMMDD-HHmm.json`
  - 加密导出文件名 `pwhelper-config-YYYYMMDD-HHmm.enc.json`
  - 加密方式为 AES-GCM + PBKDF2(SHA-256, 15 万次)，**密码不会被保存**，遗忘后无法恢复，请另行保管
- 弹层里会先显示「将导出 N 个站点 / M 套方案 / K 个字段」，确认后再落盘

### 导入

管理页签「导入」，支持两种来源：

- 选择文件：直接选上面导出的 JSON（明文或加密均可）
- 粘贴 JSON：把文件内容贴进文本框

流程：

1. **加密文件先解密**：识别到 `encrypted: true` 会出现密码框，输入密码点「解密并校验」；密码错误会提示「密码错误，或文件已损坏」，可反复重试
2. **校验并预览**：显示「N 个站点 / M 套方案 / K 个字段」，校验不通过不会写入
3. **选择合并策略**
   - **合并**（推荐）：新增的站点 / 方案 / 字段直接追加；两边都有的内容进入「冲突裁决」
   - **全量替换**：丢弃现有配置，完全以导入文件为准，不做冲突裁决
4. **冲突裁决**（仅合并策略）：逐条列出冲突，每条显示「现有」与「导入」的具体取值，用单选按钮选择保留哪一套
   - 冲突粒度：站点名称、HTTP 认证凭据、方案的自动填充开关与重试参数、字段内容
   - 敏感字段默认掩码显示，点「显示明文」可查看真实值
   - 可用「全部保留现有」/「全部使用导入」批量选择；**默认一律保留现有**，未确认前不会写入
5. 点「确认导入」落地，并提示最终的站点 / 方案 / 字段数量

## 三、配置文件格式

导出文件是格式化（2 空格缩进）的 UTF-8 JSON，方便人工维护：

```json
{
  "app": "pwhelper",
  "version": 1,
  "exportedAt": "2026-10-29T10:00:00.000Z",
  "profiles": [
    {
      "id": "p_lk3j2",
      "site": "example.com",
      "name": "示例站点",
      "matchMode": "host",
      "schemes": [
        {
          "id": "s_a1b2",
          "name": "工作号",
          "autoFill": false,
          "retry": { "times": 10, "intervalMs": 400, "initialDelayMs": 600 },
          "items": [
            {
              "id": "i_c3d4",
              "label": "用户名",
              "value": "zhangsan",
              "sensitive": false,
              "order": 0,
              "delayMs": 0,
              "submitAfter": false,
              "locators": {
                "css": "#login-username",
                "xpath": "//html/body/form/div[1]/input[1]",
                "attr": {
                  "tag": "input",
                  "id": "login-username",
                  "name": "username",
                  "type": "text",
                  "placeholder": "请输入账号",
                  "autocomplete": "username"
                },
                "strategies": [
                  { "type": "css", "value": "#login-username" },
                  { "type": "css", "value": "input[name=\"username\"]" },
                  { "type": "css", "value": "[autocomplete=\"username\"]" },
                  { "type": "xpath", "value": "//html/body/form/div[1]/input[1]" }
                ]
              }
            }
          ]
        }
      ]
    }
  ]
}
```

字段说明：

| 层级 | 字段 | 说明 |
| --- | --- | --- |
| 根 | `app` / `version` / `exportedAt` | 固定标识、结构版本、导出时间 |
| profile | `site` | 站点标识，配合 `matchMode` 匹配。可写 `example.com`（匹配该协议的默认端口 80/443）或 `example.com:8080`（只匹配该端口） |
| profile | `matchMode` | `host` **主机名 + 端口**（默认，不同端口视为不同站点）、`domain` 主域名含子域名（忽略端口）、`prefix` URL 前缀 |
| profile | `schemes` | 该站点的多套方案 |
| profile | `httpAuth` | 浏览器原生登录弹窗的凭据 `{ username, password, enabled }`，`enabled` 为 true 时自动应答 |
| scheme | `autoFill` | 是否在点开插件时自动填充 |
| scheme | `retry` | 自动填充的重试参数（次数 / 间隔 / 初始延迟，单位毫秒） |
| item | `label` / `value` | 字段标签与要填充的内容 |
| item | `sensitive` | 敏感项，列表中掩码显示 |
| item | `order` / `delayMs` | 填充顺序、填完该项后的等待毫秒数 |
| item | `submitAfter` | 填充完成后是否需要提交表单（任一字段为 true 即触发） |
| item | `locators` | 元素定位信息，`strategies` 按优先级依次尝试 |

定位策略越靠前越稳定：`id` → `name(+type)` → `autocomplete` → `aria-label` → `placeholder` → `class 指纹` → 结构 CSS 路径 → XPath。页面改版导致前面失效时会自动回退到后面的策略。

### 加密导出文件的格式

勾选「加密导出」后，`profiles` 整体被加密，只有元信息是明文（用来识别文件类型和提示输入密码）：

```json
{
  "app": "pwhelper",
  "version": 1,
  "encrypted": true,
  "exportedAt": "2026-10-29T10:00:00.000Z",
  "cipher": {
    "alg": "AES-GCM",
    "kdf": "PBKDF2-SHA256",
    "iterations": 150000,
    "salt": "Base64 随机盐",
    "iv": "Base64 随机向量",
    "data": "Base64 密文（解密后就是上面的明文 JSON）"
  }
}
```

`data` 解密后得到的正是明文版本的完整 JSON（`app` / `version` / `exportedAt` / `profiles`），因此两种格式可以互相转换。

## 四、权限与隐私

- `storage`：配置保存在本机 `chrome.storage.local`，不上传任何服务器。**本地始终是明文**，加密只作用于导出文件（防止配置文件被拷贝到别处时泄露），密码不会被保存
- `scripting` / `activeTab`：点开插件后按需把内容脚本注入当前页面（含所有 frame），用于拾取与填充
- `host_permissions: <all_urls>`：仅为按需注入做准备。**没有任何 `content_scripts` 常驻声明**，不打开插件时页面上不会运行本扩展的任何代码
- `downloads`：导出配置文件
- `webRequest` + `webRequestAuthProvider`：拦截 HTTP Basic/Digest 认证挑战，用于自动通过浏览器原生登录弹窗（该弹窗不在页面 DOM 中，无法用内容脚本填）

说明：为了可维护性与导入导出方便，配置目前是明文保存的。工具栏图标上不显示任何数字，也不会随标签页切换/页面加载去后台检查站点——所有匹配都发生在你点开插件的那一刻。如果你的机器可能被他人使用，建议后续加一层主密码加密（数据层已集中在 `src/shared/config-store.js`，接入成本很低）。

## 五、目录结构

```
manifest.json                      扩展清单（MV3）
src/shared/util.js                 通用工具：id、域名匹配、节流、转义
src/shared/schema.js               配置结构、默认值、校验、导出序列化、冲突检测与合并
src/shared/crypto.js               配置文件加解密（AES-GCM + PBKDF2）
src/shared/config-store.js         存储读写与站点匹配、拾取会话
src/shared/locator.js              元素多重定位（构建 / 回退解析）
src/shared/fill-engine.js          赋值 + 派发事件 + 等待元素 + 提交表单
src/content/content.js             拾取模式交互、填充执行（按需注入，不常驻）
src/content/picker.css             拾取浮层样式
src/background/service-worker.js   配置代理、拾取会话中转、填充转发（不巡检标签页）
src/popup/popup.html|css|js        三页签面板
test/login-demo.html               自测登录页（含受控组件模拟）
test/login-demo-iframe.html        自测页（把登录页嵌进 iframe，验证多 frame 拾取与填充）
```

## 六、常见问题

**填充时提示「未找到匹配元素」**
页面结构变了（例如 id 变为随机值）。到「管理」页删除该字段，再重新记录一次；定位信息会重新采集。

**打开的网页是空白页，只弹出一个很朴素的账号密码框**

这说明该站点用的是 HTTP Basic 认证（可用 `curl -I` 确认，响应头会有 `WWW-Authenticate: BASIC`），登录框属于浏览器自身，页面里没有输入框可拾取。按「二、使用说明 → 浏览器原生登录弹窗」录一次凭据即可，之后自动通过。

**点击「开始拾取」后页面没反应 / 点输入框没反应**
按顺序排查：

1. **刷新页面再试**：页面先于扩展加载时可能需要重新注入；现在这一步会自动兜底，若仍然失败会明确提示「无法注入到该页面」；
2. **浏览器内置页不行**：扩展商店、`chrome://`、浏览器自家内置页禁止注入脚本（任何浏览器都一样），换普通网页；
3. **输入框在 iframe 里**：已支持（内容脚本注入所有 frame），若还是不行请把页面刷新一次再开始拾取；
4. **输入框在 Shadow DOM 内**：点击时会提示「位于 Shadow DOM 内部」，这类元素无法用跨根节点的选择器复原，目前不支持；
5. **国内双核浏览器**（QQ 浏览器、360、搜狗等）请确认页面处于**极速/Chromium 模式**而非 IE 兼容模式；兼容模式下扩展无法工作。

**自动填充没生效**
1. 确认方案的「点开即填充」开关已打开，并且是从**图标**点开插件（而不是停留在已打开的面板上）；
2. 该页面若是 SPA，元素出现较晚，可在管理页把 `retry.times` 调大（默认是 10 次 × 400ms）；
3. 站点没匹配上：`a.com`、`www.a.com`、`a.com:8080` 默认是三个不同站点。跨子域名把 `matchMode` 改成 `domain`，同主机跨端口则分别记录一套方案。

**同一个域名的不同端口要用不同账号**
默认就支持：`localhost:3000` 与 `localhost:8080` 会被识别为两个不同站点，各自独立记录与填充。在非默认端口访问时，站点标识会自动带上端口号（例如 `localhost:8137`），只匹配该端口；使用默认端口（http 80 / https 443）时省略端口，此时 http 与 https 都算同一站点。

**受控组件填进去后提交时又变空**
本扩展使用原生 value setter + `input`/`change`/`keyup` 事件，已覆盖 React/Vue 常见写法；若某站点使用了特殊的输入组件，可在「管理」页给该项设置 `delayMs` 后再试。

**想换图标**
在 `manifest.json` 增加 `icons` 字段并放入 `icons/icon16.png`、`icon48.png`、`icon128.png` 后刷新扩展即可。未配置时 Chrome 使用默认图标，不影响功能。

## 七、自测

1. 用浏览器直接打开 `test/login-demo.html`（或用任意本地静态服务器托管）
2. 按「二、使用说明」完成一次记录 → 刷新 → 填充 → 导出 → 导入
3. 重点验证：账号、密码、验证码、**受控租户框**都应被正确填入，且提交时能读到值
4. 打开 `test/login-demo-iframe.html` 再录一次：验证 iframe 内的输入框能被高亮、记录并填回
